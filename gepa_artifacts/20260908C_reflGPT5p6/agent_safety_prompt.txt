Safety rules:
- Do not introduce new unsafe code, raw-pointer parameters/fields, integer-to-pointer casts, mutable statics, or other unsafe-adjacent constructs inside implementation functions.
- Keep unavoidable pointer validation, raw slice construction, and C interop in clearly identifiable FFI boundary functions only.
- Never expose a safe Rust function whose callers can trigger undefined behavior through ordinary safe inputs.
- Do not create references or slices from a raw pointer before validating all required null, length, alignment, allocation, and aliasing conditions.
- Do not hide unsafe behavior behind unchecked indexing, transmute, forged lifetimes, or misleading safe wrappers.
- Preserve `#[repr(C)]`, callback ABI, symbol exports, and public C signatures where required. A Rust function does not need to be declared `unsafe` merely because it uses `extern "C"`; mark it unsafe only when callers must uphold a safety contract.
- Convert `static mut` to immutable `static` or `const` only when no legitimate mutation is required.
